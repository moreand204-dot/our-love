# OUR LOVE — بابا & لوكه ♥

## المرحلة 1: الأساس (قاعدة البيانات + الأمان + الحسابات)

### خطوات الإعداد
1. أنشئ مشروعًا جديدًا في [Supabase](https://supabase.com).
2. **Authentication → Providers → Email**: عطّل **Allow new users to sign up** (لا حسابات عامة).
3. افتح **SQL Editor** وشغّل `supabase/001_schema.sql` كاملًا.
4. أضف بريديكما المسموحين (غيّر البريدين):
   ```sql
   insert into public.allowed_users(email, role) values
     ('your-email@example.com','owner'),
     ('her-email@example.com','partner');
   ```
5. **Authentication → Users → Add user** وأنشئ الحسابين بنفس البريدين مع كلمتي مرور قويتين.
   الـ trigger يرفض أي بريد غير موجود في القائمة.
6. **Authentication → URL Configuration**: ضع رابط Vercel في Site URL و Redirect URLs (مهم لاستعادة كلمة المرور).
7. من **Project Settings → API** انسخ `URL` و `anon key` فقط إلى `.env` (لا تضع `service_role` في الواجهة أبدًا).

### ما يغطيه الملف الآن
- جدول `allowed_users` يحصر الدخول بحسابين فقط.
- أدوار Owner/Partner وصلاحيات يعدّلها الـ Owner فقط (يُتحقق منها في قاعدة البيانات وليس الواجهة).
- أقسام ديناميكية بصلاحيات رؤية وكتابة، ومنشورات بخصوصية (خاص/مشترك) وصاحب محفوظ من الجلسة.
- شات: `client_id` لمنع التكرار، حالتا تسليم/قراءة، حذف ناعم للمرسل فقط، Realtime.
- رسائل مفاجئة: لا تظهر للمستلم قبل `reveal_at` حسب ساعة الخادم.
- Buckets خاصة (`media`, `chat`) مع حدود حجم وأنواع ملفات.

### غير منفّذ بعد (المراحل التالية)
واجهة React، الشات والتسجيل الصوتي في المتصفح، الأغاني والثيمات، التقويم، لوحة التحكم، الاختبارات والنشر.
**لم يُختبر أي شيء بعد على مشروع Supabase فعلي** — شغّل الـ SQL وأخبرني بأي خطأ يظهر.

### ملاحظة عن الإشعارات
الإشعارات داخل الموقع تعمل عندما يكون الموقع مفتوحًا. إشعارات Push عند إغلاق المتصفح تحتاج Service Worker وخدمة Web Push، وسنضيفها في المرحلة 3.

## المرحلة 2: الواجهة (Vite + React + TS + Tailwind)
```bash
npm install
cp .env.example .env   # ضع URL و anon key
npm run dev
```
**النشر على Vercel:** ارفع المشروع على GitHub ← Import في Vercel ← Framework: Vite ← أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` ← Deploy.
بعدها ضع رابط Vercel في Supabase → Authentication → URL Configuration.

الموجود: تسجيل دخول، استعادة كلمة المرور (`/reset`)، حارس يمنع أي حساب غير مصرّح، خلفية نجوم تحترم تقليل الحركة، صفحة رئيسية (ترحيب، عبارة، عدّاد المدة، بروفايل الطرفين).
**لم أستطع تشغيل `npm install` أو البناء هنا (لا يوجد اتصال بالإنترنت)، فالكود غير مُجرَّب.** لو ظهر خطأ في البناء ابعته لي.

## المرحلة 4: الشات الفوري
- شغّل `supabase/003_chat.sql` (Realtime للمرفقات + إشعار عند كل رسالة).
- `/chat`: رسائل نصية فورية محفوظة في قاعدة البيانات، حالة (✓ أُرسلت، ✓✓ وصلت، ✓✓ بالأزرق قُرئت)، مؤشر "بيكتب الآن"، رد على رسالة، نسخ، حذف للمرسل، صور (معرض/كاميرا)، تسجيل صوتي مع إيقاف مؤقت ومتابعة وعرض المدة، حالة الاتصال.
- عند انقطاع الإنترنت تُحفظ الرسالة النصية محليًا وتُعاد محاولتها بنفس `client_id` فلا تتكرر، ولا تظهر كأنها وصلت قبل تأكيد الخادم.
- المرفقات في Bucket خاص وتُعرض عبر روابط موقّعة مؤقتة (ساعة).
- **غير منفّذ بعد:** البحث داخل المحادثة وبالتاريخ، آخر ظهور، إرسال ملفات PDF، تحميل رسائل أقدم من آخر 60، مركز الإشعارات وإشعارات Push، رسائل الصور/الصوت لا تُحفظ محليًا عند انقطاع الاتصال (النصية فقط).
- لم أستطع تشغيل البناء أو اختبار الشات هنا؛ **جرّبه بحسابين على جهازين بعد النشر**: إرسال، استقبال، تحديث الصفحة، صورة، صوت، فصل الإنترنت ثم إرجاعه.

## المرحلة 5: الإشعارات + الألبوم + الإعدادات
- شغّل `supabase/004_album.sql`.
- **الإشعارات** (`/notifications`): عدّاد غير مقروء لحظي في القائمة، تعليم مقروء، وإشعار المتصفح (يعمل والموقع مفتوح في الخلفية فقط). **ما فيش Push حقيقي عند إغلاق المتصفح** — ده يحتاج Service Worker وخدمة Web Push وهو غير مضاف.
- **الألبوم** (`/album`): رفع صور (10MB، JPG/PNG/WebP) مع عنوان ووصف وتاريخ، ألبومات، شبكة متجاوبة بتحميل كسول، Lightbox، حذف لصاحب الصورة فقط، روابط موقّعة مؤقتة.

- **غير منفّذ بعد:** الصورة الشخصية وصورة الغلاف، تعديل بيانات الصورة بعد رفعها، المفضلة وغلاف الألبوم وترتيب الصور، الأغاني، الثيمات، التقويم، الرسائل المفاجئة، لوحة التحكم الكاملة، الاختبارات الآلية.

## المرحلة 6: الأغاني + الثيمات
- شغّل `supabase/005_songs_themes.sql`.
- **الأغاني** (`/songs` من الإعدادات): رفع MP3/M4A/OGG/WebM/WAV (حتى 20MB) أو رابط https، غلاف اختياري، تعيين أغنية افتراضية، حذف. **مشغّل ثابت** (تشغيل/إيقاف/سابقة/تالية/شريط تقدم/صوت/قائمة) مع زر إخفاء وتفعيل. لا يبدأ الصوت تلقائيًا؛ فقط بعد ضغط تشغيل.

## المرحلة 7: التقويم + الرسائل المفاجئة
- شغّل `supabase/006_calendar_surprises.sql`. لإشعار المستلم تلقائيًا عند حلول الموعد فعّل **pg_cron** (Database → Extensions) *قبل* تشغيل الملف، أو شغّل آخر `do $$ ... $$` بعد التفعيل.
- **التقويم** (`/calendar`): شهر بتخطيط RTL (السبت أول الأسبوع)، نقاط ملونة للأيام، قائمة "الجاية قريب"، مناسبات تتكرر سنويًا أو شهريًا، حذف لصاحب المناسبة.
- **الرسائل المفاجئة** (`/surprises`): نص + صورة اختيارية + موعد ظهور. **وقت الظهور يفرضه الخادم** (سياسة RLS تمنع المستلم من قراءة الرسالة قبل `reveal_at`، حتى لو غيّر ساعة جهازه). المستلم يشوف ظرفًا ويفتحه بحركة بسيطة.
- روابط الصفحتين من بطاقات الصفحة الرئيسية.
- **غير منفّذ:** تذكيرات المناسبات (إشعار قبل الموعد)، صورة للمناسبة، قائمة الأمنيات، لوحة التحكم الكاملة، الاختبارات الآلية.

## المرحلة 8: الأمان والاختبارات والنشر
**ترتيب ملفات SQL:** `001` → `002` → `003` → `004` → `005` → `006` → `007` (ثم أنشئ الحسابين). *إصلاح مهم في 007:* نسخة 001 كانت تنشئ الملف الشخصي قبل وجود المستخدم (كان سيفشل إنشاء الحسابين)؛ 007 يصلحه. الأفضل تشغيل 007 قبل إنشاء الحسابين.

**الأمان المطبَّق:** RLS على كل الجداول، صلاحيات تُفرض في قاعدة البيانات، Buckets خاصة بروابط موقّعة، منع التسجيل العام + قائمة بريد مسموح، دوال حساسة (`set_partner_permissions`, `apply_theme`, `set_default_song`) تتحقق من الصلاحية، رؤوس أمان وCSP في `vercel.json`، المنشور الخاص لا يظهر في السجل/الإشعارات، ولا مفاتيح سرية في الواجهة.

**إعدادات يدوية في Supabase (مهمة):** Authentication → عطّل التسجيل العام؛ اجعل الحد الأدنى لكلمة المرور 10+؛ فعّل حدود المحاولات/CAPTCHA إن وُجدت؛ Redirect URLs = رابط Vercel فقط؛ فعّل pg_cron؛ فعّل النسخ الاحتياطي.

**حدود معروفة (بصراحة):**
- ملفات مرفقات المنشورات الخاصة محمية بالمسار العشوائي وليس بسياسة لكل منشور؛ أي حساب مسجل يستطيع قراءة ملف لو عرف مساره (وهو غير قابل للتخمين).
- لا Push حقيقي عند إغلاق المتصفح، ولا آخر ظهور، ولا بحث بالتاريخ في الشات.
- لوحة التحكم المجمّعة غير مبنية كصفحة واحدة؛ وظائفها موزعة (أقسام، ثيم، أغاني، صلاحيات في الإعدادات). سجل النشاط يُسجَّل في قاعدة البيانات لكن بلا شاشة عرض.
- الوضع النهاري، قوائم التشغيل، تذكيرات المناسبات، الصورة الشخصية/الغلاف، قائمة الأمنيات: غير منفّذة.
- **لا أستطيع القول إن الموقع آمن بالكامل**: لم أشغّل أي اختبار هنا (لا إنترنت). شغّل `npm test` و`rls_tests.sql` و`TESTING.md` وراجع النتائج.
